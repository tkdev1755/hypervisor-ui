Un Observable est un flux de valeurs dans le temps. Un opérateur (dans .pipe(...)) transforme ce flux, comme une chaîne de montage. Les cinq que l'on rencontre dans le projet : • timer(0, 1000) : émet 0, 1, 2… toutes les secondes ;
• switchMap : à chaque valeur, lance un nouvel Observable (ici une requête) et abandonne la précédente si elle n'est pas finie ;
• filter : ne laisse passer que les valeurs qui conviennent ;
• take(1) : s'arrête après la première valeur ;
• tap : observe au passage, sans rien changer (journal, signal). C'est ce qui permet de suivre un clonage de VM en cinq lignes : interroger la tâche toutes les secondes jusqu'à ce qu'elle ne soit plus « en cours ». Un abonnement à un flux qui ne se termine jamais (comme timer) continue après la destruction du composant. Deux protections : take(1) si on n'attend qu'une valeur, ou takeUntilDestroyed. Les appels HTTP, eux, se terminent tout seuls. Lancez la tâche et laissez-la finir (cinq interrogations). Relancez-la, puis annulez en cours de route : le journal s'arrête net.
